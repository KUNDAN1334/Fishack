# Snowflake Integration


## Setup

To configure the Snowflake Integration in Flowlytics v2.3, specific warehouse, role, and credential requirements must be met before connecting your account. You must provide a dedicated virtual warehouse sized at least X-Small to handle analytical queries generated by the platform. The connecting user role must be granted USAGE on the target warehouse, database, and schema, along with SELECT permissions on all tables and views designated for ingestion. 

For authentication, Flowlytics supports key-pair authentication alongside standard username and password credentials. When utilizing key-pair authentication, ensure your private key is unencrypted and associated with the designated Snowflake user. Flowlytics validates all provided credentials against error code SF_AUTH_FAIL if authentication fails during setup. Verify that network policies on your Snowflake account allow inbound connections from Flowlytics IP ranges before initiating the integration.


## Sync Schedule

The Snowflake Integration v2.3 analytics feature supports hourly incremental syncs to maintain up-to-date data warehouse reporting without full-table reloads. When configured, Flowlytics queries only modified event logs and billing records since the previous watermark timestamp. 

To enable this feature, navigate to the analytics settings in v2.3 and select the hourly cadence option. Ensure your target Snowflake warehouse grants write permissions to the designated service user and that network policies allow outbound traffic from Flowlytics IP ranges. Failed sync attempts automatically trigger up to three retries at ten-minute intervals. If errors persist, the system logs error code SF-502 to your dashboard audit trail and sends an alert to the primary workspace administrator.


## Troubleshooting Sync Failures

The Snowflake Integration v2.3 analytics module handles permission errors and schema drift exceptions according to strict data governance rules. When the connector encounters an insufficient privilege error, the sync job halts immediately and logs error code SF_ERR_403. To resolve this, verify that the designated service role holds USAGE permissions on the target database and schema, as well as SELECT access on all source tables. 

Schema drift occurs when source columns are added, removed, or modified after the initial synchronization. Flowlytics v2.3 detects schema changes automatically during the pre-flight check of each scheduled extraction. If a non-compatible modification is identified, such as a dropped column or a data type mismatch, the platform flags error code SF_ERR_SCHEMA_DRIFT and pauses ingestion for the affected tables to prevent data corruption in your billing metrics. 

To recover from schema drift, navigate to the integration settings dashboard and trigger a manual schema refresh. This action updates the metadata mapping and aligns your Flowlytics analytics workspace with the current Snowflake table structure. If columns were added, they will appear in the mapping interface as unassigned fields that you can manually map to existing or new metric dimensions. Ensure that your downstream data pipelines are updated prior to executing the refresh to maintain historical continuity across your billed usage reports.
