Our async application stalls completely whenever the Python SDK flushes events. We are using version 2.4.1 of the SDK in a high-throughput FastAPI service, and the synchronous network calls inside the flush routine are blocking the main event loop. This causes massive request latency spikes and eventually triggers gateway timeouts across our entire cluster. We need an asynchronous non-blocking flush mechanism or a background worker implementation to prevent our service from freezing under load.
