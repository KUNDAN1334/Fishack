In Flowlytics v2.3, gateway timeout responses associated with error code ERR_TIMEOUT_502 now include explicit diagnostic metadata to accelerate troubleshooting. When an upstream failure or slow execution triggers this gateway error, the returned payload now explicitly identifies the specific request_id alongside the internal processing stage that timed out. This additional context allows engineering and support teams to immediately isolate latency bottlenecks across distributed pipeline components without needing to manually correlate raw telemetry logs.
