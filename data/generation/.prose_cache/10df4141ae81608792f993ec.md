The Snowflake Integration v2.3 analytics module handles permission errors and schema drift exceptions according to strict data governance rules. When the connector encounters an insufficient privilege error, the sync job halts immediately and logs error code SF_ERR_403. To resolve this, verify that the designated service role holds USAGE permissions on the target database and schema, as well as SELECT access on all source tables. 

Schema drift occurs when source columns are added, removed, or modified after the initial synchronization. Flowlytics v2.3 detects schema changes automatically during the pre-flight check of each scheduled extraction. If a non-compatible modification is identified, such as a dropped column or a data type mismatch, the platform flags error code SF_ERR_SCHEMA_DRIFT and pauses ingestion for the affected tables to prevent data corruption in your billing metrics. 

To recover from schema drift, navigate to the integration settings dashboard and trigger a manual schema refresh. This action updates the metadata mapping and aligns your Flowlytics analytics workspace with the current Snowflake table structure. If columns were added, they will appear in the mapping interface as unassigned fields that you can manually map to existing or new metric dimensions. Ensure that your downstream data pipelines are updated prior to executing the refresh to maintain historical continuity across your billed usage reports.
